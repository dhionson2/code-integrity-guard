# JSON report format

The current output uses `schemaVersion: "1.2"` and includes build status, `contractsEvaluation` (`EVALUATED` or `NOT_RUN`), `contractsManifestStatus` (`PRESENT`, `MISSING`, `EMPTY`, or `INVALID`), the evidence run UUID and project origin, contract results, separate `executionEvidence`, `declaredScenarios`, and `scenarioEvidence` arrays, PIT summary and mutation records, gate messages, and limitations. `buildStatus: AUDIT_RECORDED` means the goal produced a report; it does not imply that contracts were evaluated or approved. If contracts were not configured, `contracts` is empty and `contractsEvaluation` is `NOT_RUN`; no `VERIFIED` indicator is emitted.

PIT reports provide the class scope found in mutation rows and the separately configured `expectedScope` used by an active PIT gate. `partialCoverage` preserves the PIT XML root attribute. In PIT 1.30.2 this value is passed from `ReportOptions.shouldReportCoverage()` and defaults to true; it describes coverage metadata and does not indicate an interrupted mutation analysis. PIT results are `AVAILABLE` only when the XML is complete and compatible, current-run freshness can be established, no unresolved error states exist, and the configured expected scope matches. The denominator excludes `NON_VIABLE`; its `excluded` count is explicit.

Evidence rows carry run ID, project origin and process-unique JUnit invocation ID. Scenario evidence also contains scenario ID and observed HTTP status. Declared scenarios include policy values (type, actor/owner, resource, operation, identity header, and expected status); the HTML presents these beside observed results. HTML and JSON are written side-by-side to `target/code-integrity-guard/`.

The JSON Schema document is [json-report-schema.json](json-report-schema.json). It permits additive fields and null values in display strings. Consumers should check `schemaVersion` before strict parsing. JSON is serialized by Jackson; tests parse generated output with Gson to independently check syntax and values. HTML escaping remains a separate encoding step.
