# Proposed issue labels

The GitHub repository already has the labels `bug`, `documentation`, `enhancement`, `good first issue`, and `help wanted` (checked 2026-11-22). Keep and reuse them. The current label set also contains GitHub defaults. `needs design` is not present and is proposed as the only addition in this starter set. This is a proposal; it does not create or change labels in GitHub.

| Label | Status | Recommended use |
|---|---|---|
| `bug` | Existing | A reproducible behavior that differs from the documented contract. |
| `documentation` | Existing | A bounded correction, clarification, or addition to project documentation. |
| `enhancement` | Existing | A capability or behavior change with a verifiable expected outcome. |
| `good first issue` | Existing | Reserve for a small, self-contained issue with clear context, acceptance criteria, and no unresolved design decision. Initially apply to proposals P-01 through P-03 only. |
| `help wanted` | Existing | Apply when maintainers are actively seeking an outside contribution and can review it. It does not signal automatic acceptance. |
| `needs design` | Proposed | Use when maintainers must decide an API, schema, compatibility, or architecture direction before implementation begins. Suggested color: `#fbca04`. |

Use one type label (`bug`, `documentation`, or `enhancement`) per issue. Add `good first issue` or `help wanted` only when the issue meets the usage above. Do not use `needs design` together with `good first issue`.
